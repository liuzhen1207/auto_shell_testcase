# PROACTIVE 用例目录（设计基线）

每个用例 = **一个干净集群**（停集群 → 清 data/logs → 写 conf → 启集群）+ 一段用例体 + **收尾三件套**。
期望值一律来自 `references/proactive-spec.md`；**不得**用环境相关的观察（region 物理放置、副本落在哪台节点）当期望。

分级：`smoke`（冒烟，约 30 分钟）→ `core`（核心回归，默认）→ `full`（全量，含大规模与升级）。
协议：同一注册表在两个 conf 下各跑一遍（`IoTConsensus` 优先，`IoTConsensusV2` 其次），报告输出双协议对照表。

### PG-DEV 设备与共槽

harness 用 `pgkit/slots.py` 生成**恰好落在 K 个不同 slot** 的设备名（BKDR131 + 交叉验证 `PG-OBS-01`），
断言一律是"组数 = min(K, R)"，而不是"组数 = 设备数"。

| 用例 | 场景 | 期望 |
| --- | --- | --- |
| DEV-01..06 | 树模型 K=1,2,3,6,10,20（不同 slot，逐个建模+写入） | 逐个增长，终值 min(K,R)；Schema 与 Data 同步（均在各自上限内） |
| DEV-07..12 | 表模型同上（K 个不同 slot 的表/设备） | 同上 |
| DEV-13 | 2 个设备共槽（K=1） | 组数 1（共槽不新增） |
| DEV-14 | 3 设备落 2 slot | 组数 2 |
| DEV-15 | 单次批量请求含 K 个新 slot | 一次补齐到 min(K,R)（设计 §4.1.3 批量） |
| DEV-16 | 批量请求 = 已有 slot + 新 slot | 按并集 `K` 计（请求内重复去重） |
| DEV-17 | 连续编号设备（docs/127 覆盖更多槽） | 组数 = 实测不同 slot 数（用 harness 计算对齐），不断言设备数 |
| DEV-18 | K > R（如 R=5、K=8） | 组数封顶 R，且不再增长 |
| DEV-19 | 逐个写入的增长序列 | 与 docs §4.3.3 序列一致（5D、每库上限 ≥6 时为 1,2,3,4,5,6） |
| DEV-20 | 共槽 + 新时间分区 | 组数按 slot、时间分区不增 slot |
| DEV-21 | 1000 个不同 slot（大 K） | 组数 = R（封顶），写入/查询正确 |
| DEV-22 | 单设备多层级路径 | 1 组 |
| DEV-23 | 中文设备名（docs/127 Tree 中文） | 组数 = 实测不同 slot 数 |
| DEV-24 | 表模型含 null TAG 的设备 | 组数 = 实测不同 slot 数 |

### PG-MSR 单设备多测点（用户重点：1 设备 × N 测点）

不变量：**测点数不增加 series slot** ⇒ 单设备（1 slot）下 Schema=1、Data=1，与测点数、时间分区数无关；
数据（行数/抽样值/分区数）必须正确。≤1 万用 CLI/SQL 写；≥10 万用 benchmark 客户端（v20 表模型 / v13 树模型）。

| 用例 | 测点数 | 模型 × 时间分区 | 期望 |
| --- | --- | --- | --- |
| MSR-01..04 | 1 / 10 / 100 / 1000 | 树，1 与 3 时间分区 | 组数 1 / 1；行数=测点数×分区数；抽样值正确 |
| MSR-05..08 | 1 / 10 / 100 / 1000 | 表（1 表 N 列），同左 | 同上 |
| MSR-09..10 | 1 万 | 树 / 表，跨 3 分区 | 组数仍 1；`COUNT` 与抽样校验 |
| MSR-11..12 | 10 万 | 树 / 表（benchmark） | 组数仍 1；写入成功、抽检正确、无异常日志 |
| MSR-13..14 | 20 万 | 树 / 表（benchmark） | 同上 |
| MSR-15..16 | 50 万 | 树 / 表（benchmark） | 同上；记录耗时与资源（性能观测，不作门槛） |

## 运行策略

1. `smoke` 先跑（约 6 条 × 2 协议），失败即停并先修 harness。
2. `core` 按族顺序跑：DFT → EMPTY → DEV → MSR(≤1万) → TIME → MIN → SWCH → REB → RCV → LIM → TTL → SYS → RST → PRV → HA → OBS。
3. `full` 追加 MSR(≥10万) 与 UPG。
4. 每一例的结果目录含：`result.json`、`actions.log`、`evidence/`（组快照、SQL 输出、日志扫描三档）、必要时 `ANALYSIS.md`。
5. 双协议报告：按用例对齐两协议判定，输出差异表；判定不同的用例必须逐条给原因。
