# CRUD 用例设计说明

## 1. 与既有 skill 的关系

- 结构、配置项、执行阶段（deploy/prepare/matrix/run/report）、证据分级全部沿用 `iotdb-ttl`；
- 并发/一致性域的观测手法沿用 `iotdb-remove-cn-dn`（停机窗口外的负载、快照比对、重启与回放后比对）；
- 差异：CRUD 不需要"移除节点/注入故障"，改为**在同一集群上构造读写序列**并按断言判定。

## 2. 用例组织

格式与 TTL skill 相同：`优先级 用例ID 模型 领域 标题`（空白分隔，可对齐成列）。
- 模型：`tree` / `table`（表视图用例归 `table`）；
- 优先级：P0（核心语义，必须过）/ P1（边界与交互）。

## 3. 判定与证据

- 每条用例由若干断言组成，断言失败即 FAIL；环境不满足则 SKIP（必须写明原因，**不得**记为 FAIL）；
- 证据分级：A=真实执行且日志/SQL 返回可复算；B=真实执行但有观测限制（单拓扑/单轮）；C=文档或源码推断；
- 每条用例的 `actions.log` 必须包含：SQL 原文、服务端返回（含错误码）、关键读回结果、以及任何 props 变更与重启记录。

## 4. 预期错误码（用于断言与区分"设计内报错"与"异常"）

| 场景 | 预期 |
|---|---|
| 类型不匹配 / 非法 SQL | `700` 系列（语法/语义），数据不受影响 |
| 未设 TTL 而数据过期 | `607`（超出 TTL 范围不可写） |
| 乱序写入且 `enable_ooo=false` | 拒绝并给出明确错误码（实测确认后回填本表） |
| 路径/序列不存在 | 依模式：无模式开启时自动创建，关闭时报错 |

（本表为设计预期，**实测后**须逐条回填真实错误码，避免把"设计内报错"误判为缺陷。）

## 5. 执行器移植计划（`crudkit`）

从 `/data/deepseek/TTL/scripts/ttlkit` 派生：

1. **直接复用**：`cfg`（配置解析）、`ssh`（远端执行）、`api`（SQL/CLI 封装）、`runner`（用例调度、summary/report 生成）；
2. **替换**：`ttlcases.py` → `crudcases.py`（把 TTL 断言改为本矩阵的读写断言；`param_override` 仅保留确实需要的开关，
   如 `enable_ooo`、无模式写入、`memtable` 相关阈值）；
3. **入口**：`scripts/crud.sh` 复用 TTL 的 `ttl.sh` 骨架（子命令 deploy/prepare/list-cases/matrix/run/report）；
4. **准备阶段**：`prepare` 需设置 CRUD 相关开关并重启（`enable_ooo`、无模式写入开关、`memtable_size` 等），
   其余沿用 TTL 的"wipe + 启动 + 激活"流程（注意：**每种配置组合都需重新提交激活码**，这是 TTL 运行中踩过的坑）；
5. **运行策略**：P0 先跑一遍；一致性/并发类用例依赖负载，可复用 iot-benchmark 的 tree/table/table_view 三 workload。
