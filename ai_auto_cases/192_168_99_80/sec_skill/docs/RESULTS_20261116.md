## 三、CN/DN 日志门禁（每用例收尾自动执行）

- 判据：用例开始时间之后的 **新增** `ERROR|WARN` 行（带时间戳过滤，避免日志轮转/重启把旧行算进来）
- 白名单（`conf/env.conf: SEC_LOG_BENIGN`）：
  - `MemoryManager:285 - getOrRegisterMemoryBlock failed: memory block Consensus already exists`（每个 RPC 都打，环境噪声）
  - `ConfigExecution:223 - Failures happened during running ConfigExecution`（本套件**故意**触发 804/820 失败时产生；与 treeview 的 TV-LOG-01 是同一条噪声，研发确认随后续 commit 修）
  - Ratis/gRPC/License 等已知噪声
- 失败自动把三节点 `log_confignode_all.log`/`log_datanode_all.log` 打包到 `results/artifact_<case>_<mode>_<run_id>/logs/`

## 四、踩过的坑（重要，避免重复）

1. `password_expiration_days>0` 会让**所有老密码立即过期**（含 root/三个管理员）。曾因此把 root 锁死（822，`failed_login_attempts=5`、`password_lock_time_minutes=10`，**锁定状态持久化，重启不清**）。
   → 用例统一在开始时 `sec_conf_restore`（enforce=true / expiry=0 / reuse=0）；时间类用例只用专用用户。
2. `show configuration` 是 `| key | 生效值 | 默认值 |` 三列，取值必须取**第 3 列**。
3. CLI 一次管道多条语句时 `Msg` 会混在一起，判成功必须只看**最后一条**。
4. 用户名长度下限 **4**，太短会得到 `820: The length of name must be greater than or equal to 4`（容易误判成密码策略没生效）。
5. 三权分立开启后 root 无法登录（803）；关闭只能改配置+重启（`tools/mode_sep.sh off`）。
