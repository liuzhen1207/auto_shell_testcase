需求描述
  身份鉴别在数据库中的作用至关重要，它通过验证用户的身份来确保只有合法和授权的个体能够访问敏感数据，从而维护数据的安全性和完整性。这一过程有助于防止未经授权的访问和潜在的数据泄露，同时也为数据库操作提供了追踪具体责任人的手段，支撑审计日志等其他安全功能。简而言之，身份鉴别是数据库安全架构的基石，它为保护数据免受内部和外部威胁提供了一道关键防线。

功能定义
功能描述
身份鉴别（Authentication）：
定义：身份鉴别是指验证用户身份的过程，确保用户是他们声称的那个人。这个过程通常涉及到用户名和密码、生物识别、数字证书等验证机制。
目的：确定用户的身份，确保只有合法用户才能访问系统。
功能定义
3.2.1 identityAuthentication-001：用户名及密码的管理
需求描述
用户：用户即数据库的合法使用者。一个用户与一个唯一的用户名相对应，并且拥有密码作为身份验证的手段。一个人在使用数据库之前，必须先提供合法的（即存于数据库中的）用户名与密码，作为用户成功登录。
默认用户与角色：安装初始化后的 IoTDB 中有一个默认用户：root，默认密码为 root。该用户为管理员用户，固定拥有所有权限，无法被赋予、撤销权限，也无法被删除，数据库内仅有一个管理员用户。
密码：密码应以哈希加密的方式存储，不得以明文方式存储在数据库中。
语法描述
创建用户

CREATE USER <userName> <password>
eg: CREATE USER user1 'passwd'
删除用户

DROP USER <userName>
eg: DROP USER user1
列出所有用户

LIST USER
更新密码

ALTER USER <username> SET PASSWORD <password>;
eg: ALTER USER tempuser SET PASSWORD 'newpwd';
注意事项
一个新创建的用户或角色不具备任何权限。
用户名大小写敏感；
密码大小写敏感；
identityAuthentication-002：基于用户名密码的身份鉴别行为
基于用户名密码的身份鉴别行为是指用户在尝试访问数据库时，通过输入预先设定的用户名和密码来验证其身份的过程。这一行为定义包括以下几个关键步骤：
用户名和密码的输入：用户在请求中包含用户名和密码信息。这些信息是用户身份的标识，必须与数据库中存储的凭证相匹配。
凭证验证：数据库系统接收到用户名和密码后，会与数据库中存储的用户信息进行比对。这一过程通常涉及加密算法，以确保密码在传输和存储过程中的安全。
访问控制：如果用户名和密码验证成功，系统将允许用户访问数据库，并根据用户的角色和权限提供相应的服务。如果验证失败，系统将拒绝访问。
审计和监控：所有的身份鉴别尝试，无论成功与否，都应被记录和监控，以便于事后审计和安全分析。
 identityAuthentication-003:各类协议接入身份鉴别的方式定义
Thrift 是一种 RPC 框架，它支持多种编程语言。用户需要提供用户名和密码，Thrift 客户端将这些信息发送到服务器，服务器验证这些凭证后决定是否授权访问。
在使用 JDBC 时，IoTDB 的鉴权走的是 JDBC 接口提供的用户名密码身份鉴别的标准形式。
