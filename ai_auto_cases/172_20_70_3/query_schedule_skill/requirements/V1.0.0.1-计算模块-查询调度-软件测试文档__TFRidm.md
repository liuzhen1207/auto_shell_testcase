概述
目的
本文档是针对IoTDB 查询调度编写的软件测试文档，主要包含测试计划、测试方案和测试报告两大内容，因此在整个测试过程中将会持续更新。文档编写和维护的目的在于参考开发计划树立测试计划、测试开展过程中记录测试过程、测试结束后总结和分析测试结果、描述系统开发结果是否符合查询调度定义的各项指标。
范围
本文档适用范围：

背景和目标
背景
查询调度器（Query Scheduler）是数据处理系统（如数据库、数据仓库、大数据平台）的核心组件之一，其核心定位是对系统中待执行的查询任务（SQL 查询、数据检索请求等）进行统一管理、优先级排序、资源分配与执行调度，最终实现 “高效利用系统资源、保障关键查询响应速度、避免任务拥堵” 的目标。简单来说，查询调度器相当于数据系统的 “交通指挥官”，负责协调海量查询任务的执行顺序与资源占用，平衡 “执行效率” 与 “业务优先级”。

测试执行方案
测试人员首先将会参考功能清单（用户手册、需求和设计文档）设计测试用例，之后手动执行功能测试。包括单机和分布式功能正确性测试，后期系统稳定，满足性能测试时，使用iot-benchmark增加性能测试。并且对新版本（RC版本）发布时执行回归测试。
回归测试策略
如果在整体功能测试完成后添加了一个新功能或修复了一个缺陷，因此产生代码改变，需再次执行测试（回归测试）以验证其完整性，以防止可能的SideEffects。建议由之前的测试人员进行回归测试。
***原则上，只有在完全解决先前测试中发现的所有缺陷后，才可以申请新的测试。（如果发生异常，需要通过提前讨论确定是否进行。）
自动化测试策略
当测试人员在执行手工测试的同时，自动化测试环境也在同步的执行自动化测试，涵盖：SQL功能覆盖测试、周测写入和查询性能测试、写入效率测试、查询效率测试、合并效率测试等各种自动化测试。测试期间可根据手动测试或经验测试积累沉淀新增自动化测试场景。当测试环境发现问题时同样由测试人员复验并登记ISSUE记录，跟踪开发人员解决改善。
