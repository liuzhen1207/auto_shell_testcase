## 环境问题（阻塞复跑）

在 172.20.70.3 上**经 `tools/run_all.sh` 调用**时，用例会在"清理完成后 / 并发写入阶段"被 SIGKILL（`Killed`，rc=137），
而**单独执行同一个脚本 100% 正常**（MB-01 经 run_all 跑通、MB-03 单独跑通、MB-06 单独跑通到收尾）。
已排除：`| tee` 管道、`setsid` 会话、flock fd 继承（三种都试过仍会复现）。
`dmesg`/`kern.log`/`journalctl -k` 全为空（容器内受限），无法确认是否 OOM。
`run_all.sh` 已内置"rc=137 自动重试一次"，并在日志里明确标注为环境问题。

**补充结论（2026-10-20 22:00 定位）**：所有 `rc=137` 的用例都在**运行约 8~10 分钟后**被打断，
而 528s（≈9 分钟）的 MB-03 能跑完、801s（≈13 分钟）的 MB-06 跑不完。
⇒ 更可能是**发起端 ssh 会话被回收**（我的执行通道对长连接有上限），而不是机器 OOM：
机器 31G 内存、可用 25G、无 cgroup 限制、无 systemd-oomd、dmesg 为空。
**在真机上用本地终端/screen 跑不会有这个问题**。

**建议**：在真机上批量跑之前先单跑一条确认当轮环境；批量跑用 `tools/run_detached.sh`
（screen/tmux）或保持 ssh 存活，也可分批判跑（`--only MB-01,MB-03`）。详见 `KNOWN_ISSUES.md`。
