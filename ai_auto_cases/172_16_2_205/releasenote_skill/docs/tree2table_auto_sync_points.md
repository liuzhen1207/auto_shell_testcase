## 一、显性需求测试点

### 1.1 语法与属性

1. `CREATE VIEW ... WITH (auto_sync_schema = true) AS prefixPath` 语法可用
2. `CREATE OR REPLACE VIEW` 与 `WITH(...)` 组合可用
3. `auto_sync_schema` 不写时默认 false
4. `show create view` 能展示 `auto_sync_schema` 属性
5. prefixPath 非 `**` 结尾时报错
6. 视图 tag/time/field 列定义均可与 `WITH(...)` 共存
7. 视图指定 COMMENT，扩列后注释保持
8. `RESTRICT` 与 `auto_sync_schema` 可同时出现且互不影响
9. 创建后可通过 `ALTER VIEW ... SET PROPERTIES auto_sync_schema = false` 切换属性
10. base table 上带 `auto_sync_schema` 建表报错
11. 逻辑视图上带 `auto_sync_schema` 报错
12. 旧版本已存在的树转表视图升级后该属性为 false

### 1.2 自动补列主流程

13. 不指定 Field 列 + 开启属性 → 建视图时扫描 prefixPath 已有测点生成列
14. `INSERT` 写入自动创建序列触发补列
15. 显式 `CREATE TIMESERIES` 触发补列
16. 新增列列名为序列名小写形式
17. 原序列名含大写 → 大小写原样记为列 original_name
18. 补列后 `DESC VIEW` 能看到新列及其类型
19. 补列后查询该列能取到新序列数据
20. 新增测点与视图已有列同名（大小写不敏感）→ 不补列
21. 不补列时视图结构保持不变
22. 冲突跳过时记录 warn 日志
23. warn 日志不暴露原序列全名
24. 新增测点与已有列 original_name 大小写敏感相同 → 视为已被引用，不补列
25. 一条设备下多个新测点同批写入 → 全部补列
26. 多个设备同批写入 → 各自补列
27. 补列只在命中视图时执行
28. 一次写入命中多个视图（不同层级前缀）→ 每个视图各自补列
29. 序列被删除后视图不自动删列
30. 序列已删除时查询该列为 null
31. 已存在的列再次触发建序列 → 不重复加列

### 1.3 冲突与类型规则

32. 同名不同大小写/不同类型（dev02.s1 int32 vs 视图 s1 double）→ 不补列
33. 同名不同类型时查询不返回该序列数据
34. 同名同类型、仅大小写不同（dev01.S1 double）→ 不补列
35. 同名同类型且 original_name 命中 → 能查出该序列数据
36. 同名同类型但 original_name 不匹配（s1→d1）→ 查不出
37. 指定 Field 列 + 数据类型 → 仍扫描 prefixPath，优先按指定类型选列
38. 指定 `s1 FIELD INT32` 且存在 dev01.s1(int32) 与 dev02.s1(double) → 选 int32 那条
39. 只指定 Field 列名不指定类型 → 报错
40. 指定列类型与树模型所有同名测点都不一致 → 视为新列
41. 指定列类型不匹配时两个同名测点都查不出
42. 树模型序列类型变更不同步到视图列类型
43. 用户可手动 `ALTER VIEW` 修改列类型
44. 用户可手动新增/删除视图列
45. 模板激活到新路径 → 视为新增测点触发补列
46. `ALTER SCHEMA TEMPLATE ADD` → 所有激活该模板的路径下补列
47. 模板新增测点类型与已有列冲突 → 按冲突规则跳过
48. 模板激活时 templateId 在 DN 本地缺失 → 跳过该路径不补列

### 1.4 属性切换

49. false→true 时扫描 prefixPath 下符合要求的序列并与已有列合并
50. false→true 合并成功 → 属性变为 true
51. false→true 合并失败（类型不兼容）→ 属性保持 false
52. true→false → 功能直接关闭，不再补列
53. 关闭后再次新增测点 → 视图不变化
54. 重新开启后新增测点 → 恢复补列

### 1.5 失败与容错

55. 扩列失败不影响序列创建本身
56. 扩列失败重试耗尽后记录 error 日志
57. error 日志同时写入 log.all 与单独日志文件
58. CN 不可达时 DN 仅记 warn 日志，写入正常
59. ConfigNode RPC 超时不影响写入成功
60. 扩列失败次数计入 counter 监控项
61. 单机模式下 DN 隔离期间扩列失败 → 视图永久缺列并记录专门日志
62. 集群 ≥3 DN 时单个 DN 隔离不影响补列
63. 同一批列 leader/follower 各触发一次 → queryId 相同被去重
64. 相同 queryId 挂靠已有 procedure 等待结束，不重复加列
65. 同表不同 queryId 并发 → OVERLAP 被拦截
66. OVERLAP 后 CN 同步重试（4 轮、间隔 2s）
67. 4 轮仍冲突 → 返回失败码，DN 记日志，写入不受影响
68. 加列幂等：已存在列被过滤只加真正的缺列

### 1.6 索引与 procedure

69. DN 前缀树按路径层级下行匹配视图
70. `restrict=true` 命中条件为 numOfTags == 剩余层级
71. `restrict=false` 命中条件为 numOfTags >= 剩余层级
72. 缺 tag 列在查询时补 null
73. 同一节点可挂多个视图
74. 视图删除后引用摘除并向上剪枝空节点
75. 无视图时 getTreeToTableViews 快速短路
76. 视图改名不动前缀树挂载位置
77. 视图改 restrict/tag 数原地替换引用
78. 同一视图换 prefixPath 时先摘旧登记再挂新路径
79. DN 启动/重启/租约隔离恢复由 CN 下发全量 init 重建索引
80. init 只处理带 `__tree_path_pattern` 的视图
81. init 跳过占位表（PreDeleteTsTable / NonCommittableTsTable）
82. init 跳过路径非法的视图且不影响其他视图注册
83. 普通表变更不带 tree2TableOperationType，DN 不动索引
84. 五类建序列节点（单/对齐/多序列/内部单/内部多）均接入扩列
85. 三类模板激活节点均接入扩列
86. 模板扩展不经过 visitor 走独立分支
87. 只上报 FIELD 列，不上报 TAG 列
88. 扩列前后写入返回码不受影响

### 1.7 冲突处理口径（研发确认 2026-11-06）

89. 未声明 Field 列的树转表视图，创建时遇同名小写冲突返回 617 且视图不落库
90. 建视图时的列检测不受 `auto_sync_schema` 开关影响（不开属性同样会检测并可能 617）
91. 视图创建成功后，新增冲突测点（INSERT/CREATE TIMESERIES/模板扩展）应忽略且不报错
92. `auto_sync_schema` 由 false 改为 true 的补扫遇冲突应忽略，属性切换成功且新测点后续仍可补列

## 四、需求歧义 & 待确认清单

1. **[已确认 2026-11-06]** 建视图时 prefix 下存在 `s1`/`S1` 直接报 `617` 并创建失败，**仅创建路径**如此；新增测点/属性切换补扫一律忽略。该条不再是歧义，已转为显性测试点（见第 89~92 条）
2. **列名与 original_name 的精确规则**：文档同时说"取序列名小写作为列名"和"原序列名含大写则把原序列名作为 original_name"，当视图已有列 `s1`（original `S1`）而新序列为全小写 `s1` 时是否算"已被引用"，需明确 original_name 为空时的比较规则
3. **"同类型大小写不同时能查出数据"的判据**：`dev01.S1` 与 `s1->S1` 可查出数据，是映射到已有列查询，还是 original_name 直接命中，需确认
4. **视图列数上限**：自动扩列是否受单表最大列数限制，达到上限后的行为（拒绝/报错/静默丢弃）
5. **扩列失败后的补救**：文档称"视图永远缺列"，需确认是否有手动修复命令或重新扫描机制（关闭再开启属性是否可重扫）
6. **"一定次数的重试机制"**：DN 侧重试次数、间隔、是否指数退避均未给出；与 CN 侧"4 轮/2s/30s 窗口"是两套还是同一套
7. **counter 监控项名称与暴露方式**：文档只说"可记录一个 counter"，未给指标名、维度、上报周期
8. **单独日志文件**：文件名、路径、滚动策略、日志级别均未定义
9. **属性修改语法**：文档出现"SET PROPERTIES"与"修改该 properties"两种表述，未给具体 DDL
10. **false→true 合并失败判定**：只要有一列类型不兼容就整体失败，还是跳过不兼容列部分成功
11. **`RESTRICT` 与缺 tag 补 null**：restrict=false 时缺的 tag 列为 null，但与真实 null 值如何区分
12. **模板扩展补列的 original_name**：模板测点无原始大小写信息时，列名与 original_name 如何确定
13. **同名视图重建**：`CREATE OR REPLACE` 后原索引是否被完整摘除，是否存在残留引用
14. **视图重命名后属性是否保留**：需求未声明 rename 与 auto_sync_schema 的关系
15. **`OR REPLACE` 与属性的交互**：替换未带属性时是继承 false 还是保留原值
16. **"旧版本视图需要用新语法重建"**：重建指 `CREATE OR REPLACE` 还是 `DROP + CREATE`
17. **性能基线缺失**："未命中视图时与原来写入性能一致"无量化指标
18. **路径层级上限**：前缀树支持的最大路径层级未定义，超深路径行为未说明
19. **单机模式 DN 隔离判定**：如何构造"apply log 时处于隔离"的场景，未给判定条件
20. **DN 隔离时建序列是否返回错误**：文档说"创建序列自然也会失败"，未说明返回码与错误信息
21. **一次写入命中多视图的原子性**：部分视图扩列失败时其他视图是否成功、整体是否回滚
22. **queryId 指纹 4 字节碰撞**：SHA-256 截断 4 字节，不同列集合同 queryId 导致误去重的风险
23. **tag 列数量来源**：`ALTER VIEW ADD/DROP COLUMN` 后是否同步更新索引中的 num_of_tags
24. **`num_of_tags` 与 `RESTRICT` 的非法组合**：tag 数为 0 但 restrict=true 时行为未定义
25. **视图 prefixPath 与 database 边界**：`root.db1.**` 与 `root.db1x.**` 是否误命中
26. **模板激活触发的补列是否去重**：同一模板批量激活多路径时是否合并成一次 RPC
26. **「只声明 Field 列名不指定类型」的处理**：需求文档 3.2.2 b 明确写"不能只指定列名不指定数据类型，否则报错"，
    实测 `create view db.v(dev string tag, s1 field)` **创建成功**且类型由树模型推导，与文档描述不一致，需确认以哪边为准
27. **设备名使用保留关键字**：`root.db.region.dev01.s1` 类路径在建序列阶段即 700 解析失败，
    是否应在文档/手册中提示"设备名不要使用保留字"，或由视图创建时给出更明确提示
