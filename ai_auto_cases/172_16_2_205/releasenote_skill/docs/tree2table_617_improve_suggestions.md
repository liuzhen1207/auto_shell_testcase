## 建议 1（P1）617 报错信息补「修复指引」

### 现状

```
617: The measurements s1 and S1 share the same lower case when auto detecting type, please check
```

只有冲突双方的名字和一句 `please check`，用户不知道下一步该做什么。

### 问题

- 用户视角：我只是建个视图，为什么失败？怎么改？
- 实测的合法解法有两个，但报错里一个都没提：
  1. 在视图定义里显式声明列类型：`create view db.v1(s1 double field, dev string tag) with(auto_sync_schema=true) as root.db.**`
  2. 删除或重命名其中一个冲突测点后重建视图
- 另外报错里带了原始序列全名（`s1`/`S1`），而需求文档对**日志**有"不暴露原序列"的约束；返回给客户端的错误信息是否也受该约束，建议一并确认。

### 建议

错误信息改为（示例）：

```
617: 测点 s1 与 S1 的小写形式相同，无法自动推导视图列。
     处理方式：在视图定义中显式声明列类型（如 s1 DOUBLE FIELD），
     或删除/重命名其中一个测点后重试。
```

### 验收标准

- 触发冲突时客户端返回信息包含：冲突的两列名 + 至少一条可执行的处理方式；
- 若决定不在错误信息中暴露原始序列名，需给出替代描述（如"两个仅大小写不同的测点"）。

## 建议 2（P2）用户手册补充两条关键说明

### 现状

手册目前只有一句："创建表时可以指定列，指定列的 dataType 如果和对应的树模型的序列类型不一致，那么查询时将查不出来该序列。"

### 缺口

1. **建视图时的列检测与 `auto_sync_schema` 无关**（实测）：即使不写 `with(auto_sync_schema=true)`，只要视图未声明 Field 列，创建时同样扫描 prefixPath，同样可能因冲突报 617。手册未说明，用户会误以为"不开自动同步就不会报错"。
2. **显式声明 Field 列是官方规避手段**：需求文档 3.2.2 b 已写明"这种写法是为了规避同名测点类型冲突"，但手册没有这个操作指引。

### 建议补充段落

> **建视图时的列名冲突**
> 创建树转表视图时，若不声明 Field 列，系统会扫描 `prefixPath` 下的已有测点并自动生成列（此行为与是否开启 `auto_sync_schema` 无关）。
> 若两个测点仅大小写不同（如 `s1` 与 `S1`），无法自动推导唯一的列名，视图创建会失败并返回 617。
> 处理方式：在视图定义中显式声明列类型（如 `s1 DOUBLE FIELD`），或删除/重命名其中一个测点。
>
> **自动同步的冲突处理**
> 视图创建成功后，`prefixPath` 下新增的冲突测点**不会**导致报错，也不会进入视图（仅记录 WARN 日志），写入不受影响。

### 验收标准

- 手册树转表视图章节包含上述两段；
- 文档中给出的示例 SQL 可直接执行通过。

## 建议 3（P2）补扫失败可感知化

### 现状

视图创建后（或 `auto_sync_schema` 由 false 改为 true 时）会触发一次补扫；若补扫因冲突失败，
代码路径是 `LOGGER.warn` 后 `return Collections.emptyList()`——**用户无任何感知**。

### 问题

- 用户执行 `alter view ... set properties auto_sync_schema = true` 得到"执行成功"，但实际有列没补上；
- 后续排查只能翻 DN/CN 日志，且日志里的 warn 不指向具体视图与缺失列；
- 需求文档只提到"更新视图失败会有一定次数的重试，重试耗尽记 error 日志"，未覆盖补扫这条路径。

### 建议（三选一或组合，按成本排序）

| 方案 | 说明 | 成本 |
| --- | --- | --- |
| A. 失败计数指标 | 已在需求中提及 counter 监控项，建议落地为具体指标（如 `tree_view_auto_sync_failed_total`，带 database/table 维度） | 低 |
| B. 专门日志文件 | 与"扩列失败"共用同一个专门日志，记录 database、视图名、缺失列名、失败原因 | 低 |
| C. 状态可见 | `show create view` 或新增命令中暴露"待补列"信息，让用户能自查 | 中 |

推荐先做 A + B，C 视用户反馈再定。

### 验收标准

- 构造冲突场景（prefix 有 `s1`/`S1`，视图已建好后切 true），执行切换后：
  - 指标计数 +1（含视图维度）；
  - 专门日志中出现该视图与缺失列；
- 不改变现有行为（切换仍然成功、不报错），仅增加可观测性。
