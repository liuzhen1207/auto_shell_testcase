## 一、设计（依据需求文档 L118~L135）

| 项 | 内容 |
| --- | --- |
| 精细锁（用户@IP 级） | 同一用户从**同一地址**连续失败 `failed_login_attempts`（默认 5）次 → 锁定该 `username@ip` 组合 |
| 全局锁（用户级） | 同一用户从**任意地址累计**失败 `failed_login_attempts_per_user`（默认 1000）次 → **全局锁定该用户** |
| 名单存储 | 在 **DataNode 内存中，不持久化**（L130）；全局锁 key = `username`，精细锁 key = `username@ip` |
| 自动解锁 | `password_lock_time_minutes`（默认 10 分钟）到期自动移除 |
| 手动解锁 | `ALTER USER ... ACCOUNT UNLOCK`（L152：仅 root 或安全管理员可执行） |
| 豁免 | 本机登录的 root / 安全管理员不因密码错误被锁定（L128） |

## 二、实测对照（本版本 c05111d）

| 设计点 | 实测 | 结论 |
| --- | --- | --- |
| 精细锁：用户@IP 达 5 次锁定 | 205 → DN .2 连续 6 次错误后返回 `822 Account is blocked` | ✅ 与设计一致（AUTH-017） |
| 精细锁按 `username@ip` 生效 | 同上锁定后：从 DN .3 发起登录 .2 成功；205 登录 DN .3 也成功 | ✅ 与设计一致（key 含 IP + 名单在 DN 内存，故换 IP / 换 DN 计数独立） |
| 本机豁免（root） | 本机（.2）连续 8 次错误 → 正确密码仍可登录；远程锁定后本机仍可登录 | ✅ 与 L128 一致（AUTH-026） |
| 本机豁免（security_admin，三权分立） | 本机连续 8 次错误 → `list user` 仍成功；远程 6 次后被锁 | ✅ 与 L128 一致（AUTH-037） |
| 全局锁（用户级） | **已实测（2026-10-30）**：启动前把 `failed_login_attempts_per_user` 改为 **3**，重启集群；205 错 2 次 + .3 错 1 次（合计 3，单 IP 均未到 5）→ 205 登录 **822**、**全新来源 .4 登录同样 822** → 全局锁生效；root `ALTER USER ... ACCOUNT UNLOCK` 后 .4 恢复可登录 | ✅ 与 L120 一致 |
| 手动解锁 | normal 模式 root 可解锁；三权分立下 security_admin 返回 `701 Unsupported author type` | ⚠️ 后者为缺陷 **TDB-899**（另行跟踪） |

## 三、运维可用性结论

误锁的影响面很窄，至少有三条现成逃生路径：**换客户端 IP、登录其他 DataNode、本机登录（特权账户）**。原因是精细锁 key 为 `username@ip`，且名单是**各 DN 独立的内存结构**。

因此"root 被远程锁定导致无法运维"的担忧不成立，**无需为 root 增加全局豁免**（也会削弱防爆破能力）。

## 四、遗留项（已与研发确认设计符合预期，以下为文档/测试层面的小项）

| # | 事项 | 建议 |
| --- | --- | --- |
| 1 | 用户手册是否写明：锁定名单在 **DN 内存、不持久化**，DN 重启即清零、换 DN 独立计数 | 建议补充。这既是运维常识，也涉及安全语义（攻击者分片打不同 DN 可绕过精细锁） |
| 2 | 用户级阈值 `failed_login_attempts_per_user` 修改**需要重启**才生效 | 建议文档注明；或评估是否支持热生效 |
| 3 | `822` 提示仅 "Account is blocked"，不含被锁维度 | 可选增强：提示被锁的用户/IP，或提供查询命令便于排查 |
| 4 | 全局锁（1000 次）未纳入日常自动化 | **已完成专项验证并通过**（见 §二）；因需改配置 + 重启，仍不放进日常回归，保留脚本 `tools/probe_obs13_global_lock.sh` 供按需执行 |
